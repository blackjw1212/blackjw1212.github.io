## 0. 結論先講

1. **截圖就是 `/market/` 的預設分頁「我能領多少」。** 不是要從零做的頁面——它已經過多輪
   「依任務分組」重排，頁內註解寫著每次重排的實測理由；`market-page.test.js` 後段
   （2313–3180 行）的 48 條測試大多在釘版面、順序與文案。
2. **提案要的流程（金額 → 偏好 → 期限 → 推薦）程式裡已經有了，只是位置倒過來。**
   推薦器＝「幫我挑標的」＋問卷（`pfHorizon`／`pfLoss`／`pfMaxW`／`pfCashflow`），
   藏在頁面最下方「進階分析與說明」的**第二個折疊**裡；主畫面最上面是一個
   **要求使用者先知道代碼**的模擬器。真正的問題是資訊架構順序，不是「資訊太多」。
3. **提案有三項照做就會違反本站「不製造不可驗證數字」規則**（見 §4 E4）：
   「累積型設計」「費用率」「追蹤誤差」三者在資料裡**都不存在**。
4. **審查順帶找到 3 個既有邏輯問題**（E1、E2、E5），與介面無關、但會直接影響推薦品質。
   依提案原則，**沒有改**，列出來等你決定。

## 6. 需要你決定的事（沒有這些答案無法進第二階段）

**Q1 定位：要不要叫「推薦」？**
- (a) 維持「篩選／試算」定位，入口上移但用詞不變（例：「依你的條件挑出的組合」）——**建議**
- (b) 改叫「推薦」——要同時接受：E2 的「去年贏家」會被讀成建議，揭露要加重

**Q2 沒填所得淨額時，主入口怎麼辦？**
- (a) 問卷裡直接放「年薪」一格（重用 `simSalary`→`estimateNetIncome` 換算，不新增狀態）——**建議**
- (b) 退回稅前總報酬並明講「未計所得稅」——這會改變最佳化器現在「拒絕猜」的行為

**Q3 「不配息、累積資產」選項**
- (a) 定義為「以總報酬為目標、不要求配息」（現有 `netTotal`），明講費用率與追蹤誤差未納入、候選多為主題型——**建議**
- (b) 只篩「近 13 個月沒配過息」的標的——會混進新上市與停配的，不建議
- (c) 不做這個選項

**Q4 持有期間要不要真的影響結果？**
- (a) 修 E5：≥3 年改用 3 年回撤當閘門，期限因此真的有作用（會改變現有推薦結果）——**建議**
- (b) 不改演算法，選項合併成「3 年內／3 年以上」，誠實反映現況

**Q5 「由系統比較」**：程式沒有這個功能。做的話＝同時跑兩個目標、並排顯示，是新功能；
可以留到第二輪。

## 8. 第三輪唯讀盤點：「選了偏好卻沒有推薦」（2026-10-19，未改程式）

**重現**（本機、清空 localStorage、無 Console 錯誤）：輸入 100,000 → 結果區空白；
點「配息優先」→ 空白；點「累積資產優先」→ 空白；按「依我的情況計算」→ 才出結果。

| # | 原因 | 證據 |
|---|---|---|
| F1 | **卡片不觸發計算**（根因）。`setIntent()` 只有在 `activeProfile` 已存在（＝按過一次 pfRun）時才重算 | bind() 內 `if (activeProfile) runProfile()` |
| F2 | 金額只在「已經有結果」時才重算 | simTotal handler 的 `if ($("suggestResult").innerHTML)` |
| F3 | **ETF 載入中／失敗時沒有對應訊息**。失敗只寫進 ETF 分頁的 `#etfStamp`（本分頁看不到）；此時跑推薦會得到「沒有符合基本門檻的 ETF」——把載入失敗講成沒有合格標的 | `loadEtf()` catch；`allEtfs = []` |
| F4 | 結果區沒有**參考價與日期、可買股數、投入金額、剩餘現金、手續費**；要按「套用到下方試算」後在模擬器才看得到 | pick card 只有權重、報酬、波動、回撤、殖利率、發放月、規模、折溢價 |
| F5 | 「配息優先」的結果頂端仍顯示「以總報酬為目標等於買去年表現最好的」——那句只對累積那條成立 | runSuggest 的 banner 不分目標 |
| F6 | 累積優先沒填年薪會拒算（Q2 決定的行為，維持） | `optimizeAllocation` netTotal 分支 |

**不是原因、不需要處理的**：沒有 API 請求競態——推薦是同步窮舉（實測 115ms），
唯一的非同步是 ETF feed 載入與 300ms 防抖；「加入標的」與推薦本來就是兩條資料流
（推薦只在按「套用」時寫入 `simAllocations`）。

**提案文案不能照抄的兩句**（會變成假宣稱）：
- 「配息優先：同時評估總報酬與風險」——「補滿 12 個月」目標**只看配息現金流、不含資本利得**（方法說明原文）。
- 「累積資產優先：長期資產成長與複利累積」——目標是**近一年**稅後總報酬，不是長期複利。

**修改方案**（不動演算法）：
1. 卡片、金額（防抖）、期限／忍受跌／單檔上限／年薪／兩個勾選框，任一改變且條件齊備就自動重算。
2. 結果區四種狀態：還沒填金額或沒選偏好→一句提示；ETF 載入中→「正在載入 ETF 資料」；
   載入失敗→錯誤原文＋「重新嘗試」；無合格→維持現有原因訊息。
3. 每張結果卡加：參考價（收盤＋資料日期）、可買股數、投入金額、剩餘現金、估計手續費——
   用 `simulate()` 算，與模擬器同一個引擎，不另寫一套。
4. 結果頂端的回測警語依目標分開寫。

**根因**：累積模式的目標是「近一年**稅後**總報酬」，`optimizeAllocation()` 沒有綜合所得淨額就
拒算（2026-10-19 Q2 決定的行為）。配息模式（補滿 12 個月）不算所得稅，所以不需要年薪。
新手不填年薪 → 看到的就是一句拒算，看起來像壞掉。

**逐項排除**（提案列的十項）：切換有觸發（第三輪已修）；偏好值正確（`goal:"netTotal"`）；
不是篩選把商品全排掉（有年薪時池 11 檔）；**配息缺漏沒有被當成 0**——114 檔基本門檻內、
18 檔近一年無配息，沒有任何一檔「無配息紀錄卻有配息報酬（總報酬−價差 > 0.5pp）」；
沒有 API 競態（同步計算）；空結果不是 API 錯誤（第三輪已分開講）。

**資料能力的邊界**（不是 bug，要揭露）：
- 個股 feed 只有收盤、殖利率、本益比、淨值比、一年高低——**沒有總報酬、波動、回撤**，
  所以「讓資產長大」推不了個股，推薦範圍只有上市櫃 ETF。「ETF／全股票」分頁不影響推薦範圍。
- 「設計上不配息」的欄位不存在（§4 E4），維持現有揭露。

**實作（使用者四項都選建議）**：
- 沒年薪 → 問卷那條路以稅前總報酬排（`preTaxFallback`），結果標「未計所得稅」並講出會稍偏向配息多的標的；
  手動目標鈕照舊拒算。實測 100,000、沒年薪：00850、00878、00861、00701（與年薪 80 萬時相同）。
- 第三張卡「幫我比較兩種方式」：同一組條件兩個目標各跑一次，並排年配息、有配息月份、
  近 1 年總報酬（兩邊都用稅前）、組合中最深回撤，列出重疊標的；不判定哪一種比較好。
  實測 100,000：想領配息 年配息 6,616／總報酬 27,091／12 個月；想讓資產長大 3,695／77,113／5 個月；重疊 00878。

**提案文案不能照抄的**：「以長期資產成長為目標」——演算法看的是**近一年**；
「比較長期成果」——可以並排兩組近一年回測與配息現金流，長期只能接既有的 5／10 年投影（假設報酬率外推）。
